II. Software Requirement Specification
1. Introduction
1.1 Purpose
This document specifies the software requirements for the Hotel Booking System (Version 1.0). It defines functional, non-functional, business rules, and interface requirements to guide developers, testers, database administrators, and project stakeholders.
1.2 Scope
The Hotel Booking System is a multi-tenant enterprise hotel management and reservation platform built using Java 17, Spring Boot 4, SQL Server / PostgreSQL, and React. The system covers:
• Public & Customer Portal: Room search, real-time room locking, individual & Excel batch booking, online payment (VNPay/Stripe), customer wallet top-up, spending limit management, meal ticket purchasing, physical wristband linking, loyalty point accumulation, and voucher store redemption.
• Hotel Operations & Reception: Check-in/check-out, physical wristband pairing, meal ticket QR code scanning at restaurant areas, room maintenance matrix state tracking, and cancellation approval workflow.
• Administration & Finance: User management, customer activity logging, refund policy engine, hotel approval workflow, group pricing rules, voucher creation, system settings, and multi-dimensional reporting.
1.3 Intended Audience
This specification is intended for Software Developers, Quality Assurance Engineers, System Architects, Hotel Operations Staff, System Administrators, and Project Evaluators at FPT University.

7. Requirement Appendix
7.1 Business Rules (BR-01 to BR-20)


Rule ID

Business Rule Statement & Enforced Logic

BR-AUTH-01

Passwords must be hashed using BCryptPasswordEncoder with a strength factor of at least 12.

BR-AUTH-02

JWT tokens must expire within 24 hours. Refresh token rotation is strictly required upon renewal.

BR-ROOM-01

Room locking duration is capped at exactly 15 minutes. Unpaid locks auto-expire via background sweeper.

BR-ROOM-02

Room availability check must use optimistic locking (@Version) to prevent double reservations.

BR-PAY-01

Payment transactions are idempotent. Duplicate webhook calls with the same tx_ref must be ignored.

BR-PAY-02

Refund requests must be processed via the Refund Policy Engine based on cancellation lead days.

BR-WALL-01

Customer wallet balances cannot be negative. Overdraft attempts must be immediately rejected.

BR-WALL-02

Daily spending limit caps configured by users must be evaluated synchronously before deducting funds.

BR-MEAL-01

Meal tickets can only be redeemed within their specified validity window and designated restaurant area.

BR-MEAL-02

Physical wristbands linked to a guest meal wallet must be deactivated immediately upon guest check-out.

BR-VOUCH-01

Voucher codes are single-use per customer unless specified as multi-use promotional campaigns.

BR-VOUCH-02

Voucher discount amounts cannot exceed the configured max_discount_amount cap.

BR-LOYAL-01

Loyalty points earned equal 1 point per 100,000 VND spent on completed hotel bookings.

BR-LOYAL-02

Tier progression thresholds: BRONZE (0), SILVER (500), GOLD (1500), PLATINUM (3000 points).

BR-ADMIN-01

Hotel creation and major pricing edits require dual-authorization (Maker-Checker approval by Director).

BR-AUD-01

All financial payments, payouts, and user role modifications must produce append-only audit records.

BR-SEC-01

CORS origins must be restricted to explicitly authorized domain origins in production.

BR-SEC-02

System endpoints outside /api/auth/** and /api/rooms/search require a valid Bearer JWT.

BR-BATCH-01

Excel batch booking imports must validate row-level constraints before committing group allocations.
